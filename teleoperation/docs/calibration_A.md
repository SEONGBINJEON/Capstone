| 상태 | 리더 20 (XC430-W150) | 팔로워 15 (XC430-W150) |

| 사용자 확인 닫힘 | 68 | 916 |

리더 개폐 구간을 0~1로 환산한 뒤 팔로워 구간에 대응합니다.
구간 밖은 끝값으로 제한하며, 목표 변화 속도 제한도 적용합니다.
이 수치는 모터 축의 개폐 구간이며, 집게 사이 거리의 선형성을 뜻하지 않습니다.

## 현재 남은 단계

1. 팔로워 A 현재 자세 유지(토크 ON) 완료. 사용자가 잘 서 있음을 확인했습니다.
2. 회전 방향 확인 완료: 첫 관절은 실물 관찰, 나머지는 사용자가 확인한 동일한 축·장착 방향 설계에 근거.
3. 실제 기구에서 확인한 이동 범위 기록.
4. 읽기/추종 계산 검증 후 짧은 실물 추종.

팔로워 11번은 기준점이 단회전 범위 끝에 가깝습니다. 좌표 정규화는 토크 ON 때의 위치 표현을 맞추는 처리이며,
0/4095 경계를 넘어가는 구동 경로를 허용하지 않습니다. 넓은 양방향 가동 범위를 잡으려면 별도의 원점/조립 검토가 필요합니다.
모터 EEPROM의 Homing Offset은 변경하지 않았습니다.

## 실행 시 시작 자세

사용자는 리더를 편한 자세에 둔 상태에서 프로그램을 실행하고,
팔로워가 천천히 같은 관절 자세로 맞춰진 다음 추종하기를 선택했습니다.
매 실행 때의 상대 변위만 대응하는 방식은 사용하지 않습니다.
설정의 `startup_mode`는 `align`이며, 일자 기준점과 그리퍼 끝점 보정은 그대로 보존합니다.
정렬 속도는 최대 5°/s, 정렬 중 리더 이동 허용은 2°, 정렬 제한 시간은 60초입니다.
도착 확인 후 기존 추종으로 전환합니다. 이 기능은 가상 장치에서 검증했으며 실물 정렬은 아직 하지 않았습니다.
관절 방향과 실제 이동 범위는 미확인 상태이므로 구동 허용 표시를 변경하지 않았습니다.

## 편한 시작 자세 확인

자세 유지 프로그램을 토크 해제 없이 재개하여 리더 값도 기록했습니다.
리더 18번의 위치는 660으로, 저장된 일자 기준 2076에서 -1416 tick(약 -124.45°)입니다.
scale=1일 때 팔로워 13번 목표 후보는 방향 +1이면 579, 방향 -1이면 3411입니다.
두 값 모두 팔로워 13번의 EEPROM 위치 제한 1024~3140 밖입니다.
따라서 이 시작 자세는 방향 선택만으로 해결되지 않으며, 제한을 넓히거나 목표를 잘라 맞추지 않았습니다.
사용자에게 리더 18번을 일자 쪽으로 약 50° 덜 접어 받침에 놓도록 요청했습니다.
변경 전 자세는 `work/A_resting_pose_before_adjustment.json`에 기록했습니다.

조정 후 리더 18번은 1249(-72.69°)로 읽혔고 목표 후보 1168/2822 모두 모터 제한 안에 들어왔습니다.
첫 관절 방향 확인에서 사용자가 리더 16번을 위에서 보아 시계 방향으로 돌렸습니다.
값은 4095에서 3945로 -150 tick(-13.18°) 변했고 다른 팔 관절 변화는 2 tick 이내였습니다.
따라서 리더 16번은 이 관찰 방향에서 시계 방향 이동 시 값이 감소합니다.
사용자는 팔로워 11번의 양수 이동이 위에서 보아 반시계 방향이라고 확인했습니다.
따라서 16→11의 direction=+1을 저장했습니다. 이동 범위는 미확인이므로 reviewed=false를 유지합니다.
11번은 사용자 요청으로 양수 방향 확인 이동을 두 번 실행했습니다. 시작값 1에서 최대 59까지 움직였고
현재 약 58에서 유지합니다. 두 번 모두 5초 내의 엄격한 도착 조건을 만족하지 않아 정지 후 현재 위치 유지로 복귀했습니다.
이 위치 오차는 방향 확인 관찰을 무효화하지 않지만 정밀 도착 성능을 확인한 것으로 보지는 않습니다.
리더 16번을 시계 방향으로 돌린 현재 위치 3944는 기준 4093보다 -149 tick입니다.
확인된 direction=+1에서 팔로워 목표는 36-149=-113으로 단회전 제한 밖입니다.
다음 확인 전에 리더 베이스를 이전 위치로 되돌리도록 요청합니다. 원점 경계 문제는 아직 해결하지 않았습니다.

## 동일 축 방향 설계 확인으로 방향 검사 종료

사용자는 대응하는 모든 리더/팔로워 모터의 회전축 방향과 장착 방향을 같게 설계하고 배치했다고 확인했습니다.
추가로 팔로워 11번의 음수 방향 확인 이동이 위에서 보아 시계 방향이었음을 확인했습니다.
따라서 첫 관절에서 관측한 방향 일치와 설계 정보를 근거로 A의 팔 관절 1~4 direction=+1을 기록했습니다.
관절 2~4를 개별 실물 시험한 것으로 기록하지 않으며, 반복 방향 확인 이동은 더 진행하지 않습니다.
기존 모터 설정 기록에서도 대응 리더/팔로워 Drive Mode의 반전 비트는 동일합니다.
원점과 기구 이동 범위는 별개이므로 이 확인만으로 reviewed=true를 설정하거나 전체 추종을 시작하지 않습니다.

## 11번 원점 이동 완료

사용자가 베이스를 잡고 있음을 확인한 뒤 11번 Homing Offset을 0에서 +1024로 변경하고 읽기로 검증했습니다.
팔로워 일자 기준점을 36에서 1060으로 함께 옮겼습니다. 위 표의 36은 변경 전 기록입니다.
실제 자세 변화 없이 위치 27이 예상대로 1051로 바뀌었고, 토크 복귀 후에도 1051로 확인했습니다.
설정 백업, 11번만 토크 OFF, 원점 저장/읽기 검증, 프로그램 보정 갱신, 현재 위치 목표 설정 후 토크 복귀 순서입니다.
가상 장치에서 성공 및 오류 분기를 검증한 뒤 실물 적용을 완료했습니다. 12~15번은 토크를 해제하지 않았습니다.
백업: `work/backups/home_shift_11_1789219726835657817.json`. 현재 유지 기록: `work/hold_A_home_shift_live.jsonl`.
모터 EEPROM 위치 제한값 0~4095와 작동 모드는 변경하지 않았습니다. 전체 정렬과 추종은 아직 실행하지 않았습니다.
이동 범위에 대해 사용자는 11번은 기구상 한 바퀴, 12~14번은 링크가 겹치지 않는 범위라고 설명했습니다.
이는 수치로 확인된 충돌 없는 관절 범위가 아니므로 임의의 각도 제한을 확인 완료로 저장하지 않았습니다.

## 원점 경계 동작 시험과 확장 위치 모드 준비

원점 변경 후 실제 경계를 넘는 시험에서는 1051→목표1017에 대해 1027까지 이동 후 5초 도착 조건을 만족하지 못했습니다.
더 짧은 1027→목표1016 시험도 1026까지만 움직였습니다. 두 번 모두 현재 위치 유지로 돌아왔습니다.
사용자는 손을 놓았고 케이블이나 주변 물체가 회전을 막지 않는다고 확인했습니다.
따라서 원점 숫자 변경만으로 경계 통과가 해결됐다고 보지 않습니다. 전체 정렬은 중단한 상태입니다.
사용자가 베이스를 잡고 있다고 확인한 뒤 11번만 확장 위치 모드4로 전환하고 읽기로 검증했습니다.
초기 소프트웨어 범위는 기준1060에서 ±512 tick(좌우45°), 즉548~1572입니다. 이는 초기 제한이지 기구 전체 가동 범위 인증이 아닙니다.
모드4에서는 모터 EEPROM 위치 제한이 적용되지 않으므로 소프트웨어 범위를 읽기 검사와 모든 목표 쓰기에 적용합니다.
재시작 시 측정된 다회전 위치를 이 좁은 기준 범위에 대응시키고 회전수 차이를 세션 동안 고정합니다.
이후 뜻하지 않은 위치 점프를 새 원점으로 자동 받아들이지 않습니다. 현재 위치 유지·범위 제한·재시작 좌표 변환을 가상 장치에서 검증했습니다.
전환 중 11번 토크만 잠깐 OFF했다가 현재 위치를 목표로 설정하고 복귀했습니다. 실제 자세는 유지됐으며 12~15번은 계속 유지했습니다.
설정 백업은 `work/backups/extended_base_1789220534512537079.json`, 현재 유지 기록은 `work/hold_A_extended_base_live.jsonl`입니다.
사용자가 손을 놓았다고 확인한 뒤 짧게 시험하여 1027에서997까지, 기존1024 경계를 넘는 실제 이동을 확인했습니다.
작은 목표에서 실제 정지 오차가 5~10 tick 정도 관찰되어 최초 정밀 도착 검사가 시간 초과한 경우가 있었습니다.

## 팔 관절 초기 정렬: 거의 도착한 상태에서 중지

사용자는 현재 리더의 접힌 자세가 팔로워에서도 가능할 것 같다고 확인했습니다.
첫 연속 목표 갱신 방식에서는 14번의 시간 기반 프로파일이 반복 갱신되어 전체 목표와 차이가 커졌고 중지했습니다.
기록상 실제 위치는 모터 내부 궤적에 약5tick 차이로 따라갔으나 내부 궤적이 요청된 목표보다 늦었습니다.
최대3°의 중간 목표를 보내고 모터 내부 궤적 완료와 실제 위치의 도착을 확인한 뒤 다음 목표를 보내도록 수정했습니다.
최대 모터 프로파일 속도2°/s, 내부 궤적 대비 추종 오차3°, 리더 움직임2° 이탈 중지, 관절별 허용 범위 검사를 유지합니다.

44개 중간 목표 중 마지막 목표에서 14번의 실제 위치573, 내부 궤적539, 목표532가 기록됐고
실제-내부궤적 오차가3°를 초과하여 정렬을 중지했습니다. 당시14번 PWM은-165, 하드웨어 오류는0이었습니다.
이는 앞선 프로파일 재시작 지연과 달리 실제 모터가 내부 궤적을 따라가지 못한 상황입니다.
목표는11=911,12=3437,13=1168,14=532,15=2272이며 정지 후 현재 유지 위치는 대략914,3454,1169,574,2274입니다.
전체 정렬 성공으로 기록하지 않습니다. 사용자에게 손목14/그리퍼15 주변 링크·테이블·케이블 간섭을 확인하도록 요청했습니다.
현장 확인 전에는 추가 정렬, 힘/게인 증가, 추종 오차 제한 확대를 하지 않습니다.
현재 기록: `work/hold_A_waypoint_alignment_live.jsonl`. 요약: `work/A_alignment_partial_result.json`.
이 과정은 한 번의 시작 자세 정렬이며 기구 전체 가동 범위를 검증하거나 reviewed=true로 바꾸지 않았습니다.

## 손목 수동 확인 및 어깨 자세 차이

사용자는 외부 간섭이 없다고 답했고, 팔을 받친 상태에서 14번만 토크를 해제했습니다.
사용자는 손목이 부드럽게 움직인다고 확인했습니다. 관측된 수동 이동 구간은575~1225였으므로
이 확인이 실패 목표532까지의 기계적 통과를 입증하지는 않습니다.
14번의 새 현재 위치582를 목표로 먼저 저장한 뒤 토크를 복귀했고, 사용자가 손을 놓았다고 확인했습니다.
다른 관절의 목표·토크·통신 감시 오류는 이 절차에서 변경하지 않았습니다.

이후 사용자가17~18 링크보다12~13 링크가 아래를 향한다고 보고하여 손목 시험을 보류했습니다.
저장한 일자 기준에서17번은93.867°,12번은96.943°로 계산됩니다. 이는 독립 측정한 실제 링크 경사가 아닙니다.
12번의 대응 목표3437, 현재 유지 목표3459, 실제3472이므로 차이3.076°는
유지 목표 차이1.934°와 실제-유지 목표 오차1.143°로 나뉩니다.
18→13은 저장 기준 대비 각도가 일치합니다. 관찰만으로 원점이나 scale을 변경하지 않았습니다.

정상 자세 유지 종료 시, 내부 이동이 끝나고 정지한 관절의 기존 목표를 보존하도록 수정했습니다.
하중 아래 실제 위치를 종료 때마다 목표로 다시 저장하면 정적 오차가 누적될 수 있기 때문입니다.
진행 중 이동·오류 시 현재 위치 정지 처리와 기존 통신 감시 오류 복구 조건은 유지합니다.
반복 종료 시 오차 누적 방지, 미완료 이동 정지, 오류 보존, 확장 위치 좌표 비교를 포함해109개 테스트를 통과했습니다.
현재 실물은 추가 이동 없이 유지 중이며, 이 코드 변경으로 기존3° 차이가 교정된 것은 아닙니다.

## 수평계 측정과 제한 출력 어깨 시험

사용자는 두 베이스가 같은 수평 책상 위에 있고,17→18 링크는 수평 아래 약1°,
12→13 링크는 아래 약10°라고 확인했습니다. 실제 차이 약9°와 기존 좌표 차이 약3.1°를 비교하면
약5.9°의 상대 기준 차이가 있습니다. 측정이 근사값이므로 후보 파일만 만들고 실제 보정 설정은 바꾸지 않았습니다.
후보: `work/robot_A_shoulder_tilt_candidate.json`, 계산: `work/A_shoulder_tilt_candidate_report.json`.

사용자가 손과 휴대폰을 뗀 것을 확인하고12번만 확인했습니다. 통신 감시 정지 상태에서 프로파일 쓰기가
거부되어, 이미 저장된 저속 프로파일(가속5,속도1)을 읽어 검증하는 방식으로 수정했습니다.
기존 목표가 정지 궤적이고 현재에서2° 이내의 같은 상승 방향인지 확인한 뒤12번 통신 감시만 복구했습니다.
이는 제한된 이동 시험이며 일반 hold 재개 조건을 완화한 것은 아닙니다.
첫 이동은 실제 위치가 내부 궤적을3° 넘게 뒤따라 중지했습니다. 출력 약200 근처에서야 작은 이동이 관측됐습니다.

이후12번의 Goal PWM을885에서250으로 제한한 뒤 P Gain을800에서1200으로 변경하고 읽기로 검증했습니다.
I=0,D=0은 유지했습니다. 이 주소는 별도 A12 전용 조정 함수에만 열었으며 일반 쓰기 제한은 유지합니다.
[ROBOTIS XM430 문서](https://emanual.robotis.com/docs/en/dxl/x/xm430-w210/)의 위치 모드 출력 제한과 P Gain 정의를 확인했습니다.
최대9° 상대 상승 시험은3486→목표3384로 수행했고, 출력 제한 근처가0.5초 지속되어 중지했습니다.
약2° 상승 후 현재 유지 목표3457, 실제 약3463으로 확인했습니다. 튜닝값P1200/GoalPWM250은 현재 RAM에 남아 있습니다.
다른 관절의 토크·목표·게인·통신 감시 오류는 변경하지 않았습니다.12번은 통신 감시15, 다른 팔로워는255입니다.
보정 완료나 전체 추종 성공으로 기록하지 않습니다. 다음은 추가 출력 증가보다 지지 시 부하 변화를 확인하는 단계입니다.

정지 과정의 기록에서 통신 감시 오류 발생 전후에도 기존 목표가 현재 위치 쪽으로 바뀌는 현상이 관측됐습니다.
프로그램 종료의 목표 재저장뿐 아니라 모터의 통신 감시 정지 동작도 자세 누적 변화에 기여할 가능성이 있습니다.
불필요한 제어 프로세스 재시작을 줄이고, 재시작 전후 목표를 반드시 비교해야 합니다.
현재 로그: `work/hold_A_shoulder_tilt_check_live.jsonl`, 상태: `work/A_shoulder_output_limited_status.json`.

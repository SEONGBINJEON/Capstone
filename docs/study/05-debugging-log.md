# 05. 문제 해결 기록 — 증상 → 가설 → 확인 → 원인 → 조치

면접에서 "가장 어려웠던 문제"를 물으면 여기서 하나를 골라 이 형식으로 말하면 됩니다.

## 1. 그룹 권한을 줬는데 시리얼 포트가 계속 Permission denied
- 증상: `usermod -aG dialout` 후 로그아웃·로그인했는데도 `id`에 dialout이 없음.
- 확인: 새 프로세스의 `/proc/<pid>/status` Groups와 `systemd --user`(9월 22일 시작)의 Groups를 비교 → 같음. GNOME이 앱을 `systemd --user` 아래로 띄워서 옛 그룹을 상속.
- 원인: `KillUserProcesses=no`(기본)라 로그아웃 시 사용자 세션 프로세스가 죽지 않음.
- 조치: `loginctl terminate-user`. 교훈: "재로그인하면 반영된다"는 상식은 프로세스 트리를 확인해야 참.

## 2. 예전 보정값을 조합하니 시작 정렬량이 200°
- 확인: 리더·팔로워 각 관절의 기준점 대비 편차를 표로 비교. 베이스는 정확히 180° 어긋남, 나머지 관절은 크기 비슷·부호 반대.
- 원인 두 가지: 리더 베이스 기준점이 반 바퀴 틀렸음(12 → 2060), 그리고 그 순간 두 팔의 자세가 실제로 달랐음.
- 조치: 기준점 수정 + 사용자가 리더를 되돌린 뒤 절대 기준으로 정렬. 임시로 `--match`(현재 자세를 동일하다고 가정)를 썼지만 자세가 어긋나는 부작용을 확인하고 기본을 절대 기준으로.

## 3. 접힌 자세에서 토크를 켤 수 없음(ID 13)
- 증상: 현재 위치 605, 모터 EEPROM 제한 1024~3140.
- 확인: 같은 설계의 다른 팔(ID 23)은 0~4095. 예전 기록에도 같은 문제로 팔을 50° 덜 접어 회피한 흔적.
- 조치: 사용자 확인 후 EEPROM 제한을 0~4095로 변경, 이전 값 백업. 교훈: 모터 안의 설정도 "상태"다. 변경 이력을 문서화.

## 4. 추종이 갑자기 멈춤(첫 번째)
- 증상: "ID 14 추종 오차 13° 초과" 후 대기, 재개 조건(리더를 팔로워 자세 3° 이내로)이 너무 엄격해 복귀 불가.
- 원인: 목표가 실제보다 21°까지 앞서갈 수 있게 해놓고 허용 오차는 12° → 빠른 손 동작에서 반드시 걸리는 설정 모순.
- 조치: 선행 10°, 허용 20°, 1초 후 자동 재개.

## 5. 팔로워 링크1이 리더와 반대 방향
- 원인: `--match`로 시작하면서 다른 자세를 같다고 가정.
- 조치: 절대 기준 시작. 교훈: 편의 기능이 보정 오류를 숨길 수 있다.

## 6. Isaac Sim에 로봇이 안 보임(두 가지 원인이 겹침)
- 확인 1: USD를 순회해 `UsdGeom.Mesh` 개수 → 0. URDF 메시 경로가 `package://assets\follower_01.stl`(역슬래시). 변환기가 STL을 못 찾음.
- 조치 1: 경로를 `assets/…`로 고친 URDF를 재변환 → geometries.usd 1.7 MB 생성.
- 확인 2: 그래도 안 보임. 바운딩 박스를 찍어 보니 z = −0.44~−0.23 → 내가 깐 바닥판(z=0) 아래.
- 조치 2: 바닥을 로봇 최하점 아래로, 카메라 자동 프레이밍. 헤드리스 캡처로 직접 확인.
- 교훈: "안 보인다"는 증상 하나에 원인이 둘 이상일 수 있다. 하나 고치고 끝내지 말고 결과를 눈으로 확인.

## 7. 네트워크 에셋을 넣으면 렌더가 검게 나옴
- 확인: 소품 없이는 정상, 소품마다 바운딩 박스는 정상 크기, 조명·카메라 프림 없음, 500프레임 기다려도 검음.
- 판단: 원인을 끝까지 못 밝힘(텍스처/MDL 로딩 추정). 시간 대비 가치가 낮아 옵션으로 격리(`--props`)하고 절차적 소품으로 대체.
- 교훈: 모든 문제를 끝까지 파지 않는 것도 판단. 단, 격리해 두고 기록에 남긴다.

## 8. 과부하로 모터가 스스로 토크를 끔(ID 13, 0x20)
- 확인: 정지 직전 로그에서 3번 관절만 9.5° 차이가 수십 주기 유지됨 → 걸린 채 밀고 있었음. 리더 목표 위치가 예전 제한 바깥의 기구 한계 근처.
- 조치: Reboot 명령으로 오류 해제. 걸림 감지(1.4초 무진행) 추가, 리더가 되돌아올 때만 재개.
- 교훈: 안전 임계값은 "모터가 스스로 보호하기 전에" 소프트웨어가 먼저 멈추도록 잡는다.

## 9. 재개 후 계속 저속
- 원인: blocked → aligning으로 돌아가는데 끝까지 못 가는 관절이 있으면 정렬 종료 조건을 영원히 만족하지 못함.
- 조치: 재개는 following으로, 현재 위치에 앵커.

## 10. 자세 자동 탐색이 목표에 못 감(오차 0.6 m)
- 확인: FK 디버그로 관절 하나씩 돌려 링크 위치 출력 → 3번 관절은 양수가 앞으로 접히는 방향인데 탐색 범위를 음수로만 잡았음. 두 번째는 "손가락이 아래를 향함" 판정을 링크 원점 높이로 했는데 원점이 거의 같은 높이라 무의미 → 쿼터니언으로 방향 벡터 계산.
- 세 번째: 탐색 중 팔이 강체 프라이팬을 쳐서 밀어냄 → 렌더용 팬은 고정.

## 공통 패턴

1. 증상을 **숫자로** 만든다(각도 차이, 바운딩 박스, 프로세스 그룹). 
2. 가설마다 **가장 싼 확인 방법**을 먼저(읽기 전용 스캔, 헤드리스 캡처, dry-run).
3. 고친 뒤 **결과를 직접 본다**(이미지, 로그).
4. 되돌릴 수 없는 변경(EEPROM, 삭제)은 백업과 확인을 거친다.

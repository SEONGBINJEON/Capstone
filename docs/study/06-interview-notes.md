# 06. 면접 노트

## 1분 설명

"주방 반복 작업용 4자유도 팔을 직접 설계·제작하고, 리더 암으로 팔로워 암을 실시간 조작하는 텔레오퍼레이션 시스템을 구현했습니다. DYNAMIXEL 서보 10개를 Protocol 2.0 sync read/write로 20 Hz 제어하고, 속도 제한·watchdog·걸림 감지 같은 안전 계층을 소프트웨어로 넣었습니다. 팔로워의 관절 상태를 UDP로 Isaac Sim에 보내 URDF 모델이 실물과 동시에 움직이는 디지털 트윈을 만들었고, 이 시뮬레이션 환경을 이후 모방학습 데이터 검증에 쓰는 것이 다음 단계입니다."

## 3분 설명에 덧붙일 것

- 왜 리더-팔로워인가: 사람의 시연 데이터를 가장 싸게 모으는 방법. 모터 tick을 그대로 기록하면 관절 공간 데이터가 됨.
- 안전 설계: 토크 ON 순서(현재 위치를 목표로 먼저), Bus Watchdog 300 ms, 15°/s 정렬 후 180°/s, 추종 오차 20°·걸림 1.4 s에서 자세 유지, EEPROM 쓰기 차단.
- 실제 사고 한 건과 대응: 과부하 → 걸림 감지 추가(05번 문서 8번).
- 디지털 트윈: URDF→USD 변환 문제(경로, 좌표)를 직접 진단, 두 프로세스 분리로 시뮬 장애가 로봇에 영향 없음.
- 시뮬 활용: 100대 병렬 인스턴스, 샘플링 기반 자세 탐색.

## 예상 질문과 답의 뼈대

**Q. 지연은 얼마나 되고 어디서 생기나?**
루프 50 ms + 모터 프로파일 50 ms + 선행 제한. 체감 100~150 ms. 줄이려면 주기 단축(sync read 시간이 한계), 프로파일 시간 단축, 선행 한계 완화(안전과 트레이드오프).

**Q. 왜 ROS를 쓰지 않았나?**
프로세스 2개, 메시지 1종이라 UDP JSON으로 충분. ROS 2 도입은 카메라 동기 수집 단계에서 검토(타임스탬프, bag 기록).

**Q. 팔로워가 장애물에 부딪히면?**
두 경로: 모터 내부 궤적과 실제 위치 차이 20° 초과(빠른 충돌), 목표와 5° 차이가 있는데 1.4초 무진행(느린 걸림). 둘 다 현재 위치 유지로 전환, 토크는 유지. 걸림형은 리더가 반대로 돌아올 때만 재개.

**Q. 보정은 어떻게 했나?**
같은 물리 자세(일자)에서 양쪽 tick을 기준점으로 저장, 방향 부호는 같은 방향으로 돌려 확인, 그리퍼는 개폐 비율 매핑. 기준점 하나가 반 바퀴 틀려 있던 것을 편차 표로 찾아냈음.

**Q. 시뮬레이션과 실물의 차이는?**
현재는 표시용(각도만 반영). 동역학·접촉은 아직 안 맞춤. 다음 단계는 시뮬에서 정책 검증 → 실물.

**Q. 가장 어려웠던 점?**
05번 문서에서 6번(안 보이는 로봇, 원인 둘) 또는 8번(과부하) 추천.

**Q. 다시 하면 바꿀 것?**
설정 변경(EEPROM) 전에 기구 한계를 먼저 측정했을 것. 리더 쪽 가동 범위를 팔로워 기구 한계로 제한하는 것을 처음부터 넣었을 것. 뷰어에 조인트 방향 확인용 오버레이를 먼저 만들었을 것.

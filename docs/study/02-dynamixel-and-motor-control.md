# 02. DYNAMIXEL 통신과 모터 제어

## Protocol 2.0 핵심

- 반이중 직렬 버스(TTL/RS-485). 한 포트에 여러 모터가 ID로 구분되어 매달림. 이 프로젝트는 1 Mbps.
- 명령 = 컨트롤 테이블의 **주소**에 **바이트**를 읽고 쓰는 것. 모터 종류가 달라도(XL330, XL430, XM430, XC430) 주요 주소가 같아서 코드 하나로 다룰 수 있습니다.
- 자주 쓴 주소(모두 X 시리즈 공통):

| 주소 | 항목 | 크기 | 메모 |
|---|---|---|---|
| 10 | Drive Mode | 1 | bit2=시간 기반 프로파일, bit0=회전 방향 반전 |
| 11 | Operating Mode | 1 | 3=위치, 4=확장 위치(다회전), 0=전류 |
| 20 | Homing Offset | 4 | 원점 이동 (EEPROM) |
| 48/52 | Max/Min Position Limit | 4 | EEPROM. 목표가 이 밖이면 Range Error로 거부 |
| 64 | Torque Enable | 1 | 1이면 EEPROM 쓰기 불가 |
| 70 | Hardware Error Status | 1 | bit5(0x20)=과부하, bit0=입력 전압 |
| 98 | Bus Watchdog | 1 | 단위 20 ms. 15 → 300 ms 동안 명령이 없으면 정지, 255=오류 래치 |
| 108/112 | Profile Acceleration/Velocity | 4 | 시간 기반이면 ms 단위 |
| 116 | Goal Position | 4 | |
| 132 | Present Position | 4 | 확장 모드에서는 다회전 누적값(부호 있음) |
| 144/146 | Present Voltage/Temperature | 2/1 | |

- **Sync Read / Sync Write**: 여러 ID의 같은 주소 구간을 패킷 하나로 읽고 씁니다. 20 Hz 루프에서 모터 10개를 개별로 읽으면 시간이 안 나오므로 필수입니다. `Rig.sample()`은 주소 64~146(83바이트)를 한 번에 읽어 위치·토크·온도·전압·오류·watchdog·궤적을 동시에 얻습니다.
- **상태 패킷의 오류 바이트**: 하위 7비트가 오류 코드, bit7은 "Hardware Error Status에 무언가 있다"는 경고. 리더 그리퍼(XC430)는 4.5 V 전원 때문에 이 경고가 항상 켜져 있어, `TolerantRig`가 "경고 비트만 있고 코드가 0"인 경우를 통과시킵니다. 실제 하드웨어 오류는 주소 70을 따로 읽어 판단합니다.

## 위치 제어 모드와 좌표

- 모드 3(위치): 0~4095 한 바퀴. 목표가 0/4095 경계를 넘는 궤적은 만들 수 없습니다.
- 모드 4(확장 위치): 다회전 누적 tick. 베이스(ID 11)가 이 모드입니다. 소프트웨어에서 "논리 좌표"를 정의해야 합니다.
  - `extended_position: {reference, raw_reference, min, max}`: 원시값 `raw_reference`가 논리값 `reference`에 대응. `Rig`는 시작 시 `(raw − raw_reference + 2048) % 4096 − 2048`로 가장 가까운 회전을 잡아 `turn_offset`을 정하고, 이후 목표는 `logical + turn_offset`으로 되돌립니다.
  - 이번에 ±45°(548~1572) → ±179°(1~4095)로 넓히면서 `reference`를 2048로 옮긴 이유: 창의 양쪽이 2048 미만이어야 하고 0~4095 안에 들어야 하므로, 대칭 ±179°를 얻으려면 중심이 2048이어야 합니다.
- Homing Offset이 있으면 토크 OFF 때 읽히는 값과 토크 ON 직후 좌표가 달라질 수 있어 `position_mode_coordinate()`가 보정합니다.

## 프로파일(부드러운 이동)

- Drive Mode bit2=1(시간 기반)이면 Profile Velocity/Acceleration이 ms 단위. `stream_goals()`는 "이번 목표까지 50 ms에 도달, 가속은 그 1/4"처럼 매 주기 프로파일을 새로 씁니다. 50 ms마다 목표를 갱신하므로 사실상 연속 궤적이 됩니다.
- bit2=0(속도 기반)인 XM430(ID 12), XC430(ID 15)은 rpm 단위 `velocity = deg/s ÷ 6 ÷ 0.229`로 바꿔 씁니다.

## 안전과 관련된 모터 기능

- **Bus Watchdog**(주소 98): 팔로워마다 15(300 ms)로 설정. 제어 프로그램이 죽거나 USB가 빠지면 모터가 스스로 목표 갱신을 멈춥니다. 종료 시 0으로 되돌려 자세 유지가 유지되게 합니다. 값이 255면 "타임아웃이 발생했음"이 래치되어 0을 써서 지워야 합니다.
- **과부하(0x20)**: 전류가 오래 크면 모터가 토크를 스스로 끊고 오류를 래치. 지우려면 Reboot 명령(`reboot_motor.py`) 또는 전원 재투입. 이번에 3번 관절이 기구 한계에 걸린 채 계속 밀어서 발생했고, 이후 "걸림 감지"를 소프트웨어에 추가했습니다.
- **EEPROM 쓰기**는 토크 OFF에서만 가능하고 영구적입니다. `Rig.write()`는 허용 주소 5개(64, 98, 108, 112, 116)만 쓰게 막아 두었고, EEPROM 변경은 별도 도구(`set_position_limits.py`)로만 하며 이전 값을 파일로 백업합니다.

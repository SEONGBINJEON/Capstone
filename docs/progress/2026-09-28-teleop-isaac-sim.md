# 2026-09-28 — 텔레오퍼레이션 재구축 + Isaac Sim 디지털 트윈

## 목표
리더 암(모터 26~30, OpenRB-150)으로 팔로워 암(모터 11~15, OpenCR)을 그리퍼까지 실시간으로 조작하고, 같은 PC의 Isaac Sim에서 팔로워 URDF 모델이 동시에 움직이게 한다. 이후 발표용 이미지 확보.

## 환경 문제와 해결
- USB 시리얼 권한: `dialout` 그룹에 추가했지만 로그아웃해도 반영되지 않음. 원인은 `systemd --user`가 로그아웃 후에도 살아 있어 GNOME이 띄우는 앱이 옛 그룹 목록을 물려받은 것. `sudo loginctl terminate-user <user>` 후 재로그인으로 해결.
- 시스템 python3(3.10)에 pip이 없고 가져온 venv는 다른 PC용이라 깨져 있음. Isaac Sim의 python으로 wheel만 내려받아 `teleoperation/vendor/`에 `dynamixel_sdk 4.0.5`, `pyserial 3.5`를 동봉.

## 하드웨어 확인
| 보드 | 포트 | 모터 |
|---|---|---|
| OpenCR (팔로워) | `/dev/ttyACM0` | 11 XL430-W250(베이스, 확장 위치 모드) · 12 XM430-W210 · 13 XL430 · 14 XL430 · 15 XC430-W150(그리퍼) |
| OpenRB-150 (리더) | `/dev/ttyACM1` | 26~29 XL330-M288 · 30 XC430-W150(그리퍼) |

- 리더 그리퍼 30번은 OpenRB의 4.5 V 전원 때문에 XC430의 전압 경고 비트가 항상 켜져 있음. 읽기 전용이므로 코드에서 이 비트만 예외 처리.

## 텔레오퍼레이션 구현 (`sim_teleop/`)
- 기존 코드의 모터 접근 계층(`teleop/hardware.py`의 Rig: 확장 위치 모드 처리, 배타적 포트, watchdog)을 재사용하고 그 위에 26→11 … 30→15 전용 루프를 새로 작성.
- 시작 시 15°/s 저속 정렬 → 180°/s 추종. 팔로워 통신 watchdog 300 ms. 리더 토크 ON이면 시작 거부. Ctrl+C 시 자세 유지(토크 ON).
- 팔로워 관절 각도를 UDP(127.0.0.1:5005) JSON으로 발행 → Isaac Sim 뷰어가 수신.

### 보정 이슈
- 예전 A/B 보정값(리더 B 기준점 + 팔로워 A 기준점)을 그대로 조합하면 시작 정렬량이 200° 이상. 원인 1: 리더 26(베이스) 기준점이 180° 틀어져 있었음 → 12에서 2060으로 수정. 원인 2: 리더가 놓인 자세가 팔로워와 달랐음. 수정 후 절대 기준 정렬이 몇 도 이내로 맞음.
- 팔로워 13번이 접힌 자세(약 600 tick)일 때 모터 EEPROM 위치 제한(1024~3140) 밖이라 토크를 켤 수 없었음. 같은 설계의 다른 팔(B 팔로워 23)은 0~4095였으므로 13번도 0~4095로 변경(백업 보관).
- 팔로워 11번(베이스)의 소프트웨어 범위가 기준 ±45°로 잡혀 있어 크게 돌지 않았음 → 기준 좌표를 2048로 옮겨 ±179°로 확대.

### 사고와 보호 추가
- 13번이 기구 한계에 걸린 채 리더 목표를 향해 계속 밀다가 과부하 오류(0x20)로 모터가 스스로 토크를 끄고 안전 정지. `reboot_motor.py`로 오류 해제 후 재시작.
- 걸림 보호 추가: 목표와 5° 이상 차이가 나는데 1.4초 이상 움직이지 않으면 자세 유지로 전환하고, 리더의 해당 관절을 되돌리면 재개.
- 대기 후 재개 시 저속 정렬로 돌아가 15°/s에 머무는 문제 → 재개 시 바로 180°/s로 복귀하도록 수정. 추종 오차 허용 12°→20°, 목표 선행 한계 10°.

## Isaac Sim 디지털 트윈
- 처음에는 모델이 보이지 않았음. 원인 1: URDF의 메시 경로가 `package://assets\follower_01.stl`(윈도우 역슬래시)라서 변환 시 STL을 못 찾아 USD에 메시가 없었음 → 경로를 `assets/…`로 고친 `robot_isaac.urdf`를 Isaac 임포터로 재변환. 원인 2: URDF 0° 자세에서 형상이 z<0에 있어 뷰어 바닥판 아래에 묻힘 → 바닥을 로봇 최하점 아래로, 카메라 자동 프레이밍, 조명 추가.
- URDF 0° 자세는 팔이 눕고 베이스가 세워진 방향이라 루트를 X축 90° 회전시켜 표시.
- 관절 부호: 1번 베이스 화면 회전이 실물과 반대 → 뷰어 쪽 `view_sign=-1`.
- Fin-Ray 핑거 재질을 파란색으로 변경.
- 주방 장면: 작업대·하부 수납장·타일 벽·선반·인덕션·도마·수건·접시·머그·향신료·칼 블록, 미니 프라이팬(지름 90 mm, 손잡이 85 mm) 2개. Isaac 에셋 서버 소품은 텍스처 로딩 문제로 렌더가 검게 나와 기본 비활성.
- 뷰어 실행 중 `touch work/capture_request`로 스크린샷 저장.

## 발표용 렌더 (`render_gallery.py`, `media/renders/`)
- 팔로워 100대 10×10 병렬, 주방 환경 3×3 병렬, 히어로 샷, 그리퍼 클로즈업, 파지 시퀀스(접근·파지·들기), 탑뷰. 모두 Isaac Sim 장면 연출이며 실제 학습 결과가 아님.
- 파지 자세는 시뮬레이션에서 수천 개 관절 조합의 그리퍼 위치·방향을 읽어 프라이팬 손잡이 위 목표에 가장 가까운 조합을 자동 선택.
